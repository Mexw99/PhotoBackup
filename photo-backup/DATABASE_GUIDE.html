Complete Database & Architecture Guide

คู่มือฉบับละเอียดสำหรับทำความเข้าใจโปรเจกต์ PhotoBackup ตั้งแต่ Wails เปิดโปรแกรม, SQLite ถูกสร้างตรงไหน, GORM แปลง Model เป็นตารางอย่างไร, Repository เขียน Query แบบไหน, ไปจนถึงการไหลของข้อมูลจาก Nuxt ผ่าน Wails และกลับมาแสดงผลบนหน้าจอ

Wails v2 · Go · Nuxt 4 · GORM · SQLite · ใช้ได้บน Windows และ macOS

2. หน้าที่ของแต่ละชั้น

Frontend Layer

รับ input จากผู้ใช้ เช่น Path, ชื่อ Tag และตัวเลือก AND/OR จากนั้นเรียกฟังก์ชันที่อยู่ใน frontend/wailsjs/go/main/App.js

Frontend ไม่ควรเปิดไฟล์ SQLite เอง และไม่ควรเขียน Query SQL เอง

Wails Presentation Layer

main.go ทำให้ App object ถูก Bind ส่วน app.go เป็น public method ที่ Wails แปลงเป็น JavaScript API

Layer นี้แปลงข้อมูลระหว่างโลกของ Vue และโลกของ Go

Repository Layer

รวมคำสั่งอ่าน/เขียน Database ให้เป็นจุดเดียว ช่วยไม่ให้ app.go เต็มไปด้วยรายละเอียด SQL และช่วยให้ Test ง่ายขึ้น

Database Layer

ควบคุมตำแหน่งไฟล์, Connection, Migration และการปิด Resource ไม่ควรเอา Business logic ของ Tag หรือ Search มาไว้ชั้นนี้

4. ตำแหน่งไฟล์ SQLite

ไฟล์หลักคือ internal/database/database.go และฟังก์ชันที่กำหนดตำแหน่งคือ DefaultPath() 

func DefaultPath() (string, error) {
  baseDir, err := os.UserConfigDir()
  if err != nil {
    return "", err
  }

  return filepath.Join(
    baseDir,
    appDirectoryName,
    "photo-backup.db",
  ), nil
}

ทำไมไม่เขียน Path ตายตัว

ถ้าเขียน C:\\Users\\ชื่อคน\\... โปรแกรมจะใช้กับเครื่องอื่นไม่ได้ และถ้าเขียน /Users/name/... ก็จะไม่เหมาะกับ Windows

ทำไมใช้ filepath.Join

Go จะเลือกตัวคั่น Path ที่เหมาะกับ OS โดยอัตโนมัติ เช่น \\ บน Windows และ / บน macOS

จำง่าย: os.UserConfigDir() เลือกฐาน Path, PhotoBackup คือโฟลเดอร์ของ App, และ photo-backup.db คือไฟล์ Database จริง

5. เปิด SQLite Connection

ฟังก์ชัน OpenAt(path) ทำงานตามลำดับ: ตรวจ Path → สร้างโฟลเดอร์ → เปิด GORM → Migrate 

func OpenAt(path string) (*Database, error) {
  if path == "" {
    return nil, errors.New("database path is empty")
  }

  directory := filepath.Dir(path)
  if err := os.MkdirAll(directory, 0755); err != nil {
    return nil, err
  }

  conn, err := gorm.Open(sqlite.Open(path), &gorm.Config{})
  if err != nil {
    return nil, err
  }

  return &Database{conn: conn}, nil
}

ตัวแปรแต่ละตัวคืออะไร

ตัวแปรประเภทความหมาย
pathstringตำแหน่งไฟล์ SQLite
directorystringโฟลเดอร์ที่เก็บไฟล์ Database
conn*gorm.DBตัวเชื่อมต่อที่ GORM ใช้ Query
Database.conn*gorm.DBเก็บ connection ไว้ภายใน struct

6. AutoMigrate ทำอะไร

AutoMigrate อ่านโครงสร้างจาก Model แล้วตรวจว่าตาราง/คอลัมน์ที่จำเป็นมีหรือยัง ถ้ายังไม่มีจะสร้างให้โดยไม่ต้องเขียน CREATE TABLE เองในโค้ด 

if err := conn.AutoMigrate(
  &models.Photo{},
  &models.Tag{},
); err != nil {
  return nil, err
}

ครั้งแรก

สร้างตาราง photos, tags และ schema ของความสัมพันธ์

ครั้งถัดไป

ตรวจตารางเดิมและพยายามปรับให้ตรงกับ Model โดยไม่ลบข้อมูลเดิม

เมื่อเพิ่ม Field

ต้องตรวจว่า Migration ทำงาน และต้องปรับ Repository ให้ใช้ Field ใหม่ถูกต้อง

ข้อควรระวัง: AutoMigrate ไม่ได้แปลว่าการเปลี่ยน Schema ทุกแบบปลอดภัยเสมอ ควร Backup Database ก่อนการเปลี่ยน Model ใหญ่ ๆ

7. Model Photo

อยู่ที่ internal/models/photo.go และแทนข้อมูลรูปภาพหนึ่งรายการในระบบ 

type Photo struct {
  ID           uint      `gorm:"primaryKey"`
  OriginalName string    `gorm:"not null"`
  OriginalPath string    `gorm:"not null"`
  BackupPath   string    `gorm:"not null;uniqueIndex"`
  FileSize     int64     `gorm:"not null;default:0"`
  BackedUpAt   time.Time `gorm:"not null"`
  CreatedAt    time.Time
  UpdatedAt    time.Time
  Tags         []Tag `gorm:"many2many:photo_tags;"`
}
Fieldความหมายใช้ที่ไหน

OriginalPathตำแหน่ง Flash Driveเก็บแหล่งที่มาของรูป
BackupPathตำแหน่งไฟล์ที่คัดลอกแล้วใช้เปิด/แสดงไฟล์ และกัน Path ซ้ำ
FileSizeจำนวน byteแสดงรายละเอียดและตรวจผล Copy
BackedUpAtเวลาที่สำรองเรียงรูปล่าสุด

UpdatedAtเวลาแก้ rowGORM จัดการอัตโนมัติ

uniqueIndex ที่ BackupPath: ช่วยไม่ให้มี Photo สอง row ใช้ตำแหน่ง Backup เดียวกัน แต่การกันชื่อไฟล์ซ้ำตอน Copy ยังต้องทำใน internal/backup ด้วย

8. Model Tag

9. ความสัมพันธ์ Photo, Tag และ PhotoTag

ระบบใช้ Many-to-Many เพราะรูปและ Tag ต่างฝ่ายต่างมีได้หลายรายการ

photos 1 ───── หลาย photo_tags หลาย ───── 1 tags

ตัวอย่างข้อมูล

Photo 10 คือรูปทะเล อาจมี Tag 1 = ทะเล และ Tag 2 = ทริป

Tag 1 = ทะเล อาจถูกใช้กับ Photo 10, Photo 11 และ Photo 20

12. เพิ่ม Tag ให้หลาย Photo

ฟังก์ชัน AddTagToPhotos เป็นตัวอย่าง Business operation ที่ต้องทำหลายขั้นตอนใน Transaction

  1. Trim ช่องว่างหน้าหลังชื่อ Tag
  2. ปฏิเสธชื่อว่างด้วย ErrEmptyTagName
  3. ปฏิเสธกรณีไม่ได้เลือก Photo ด้วย ErrNoPhotoIDs
  4. ตัด ID ซ้ำด้วย map
  5. เปิด Transaction
  6. ใช้ FirstOrCreate ป้องกัน Tag ซ้ำ
  7. โหลด Photo ตาม ID
  8. ตรวจว่าจำนวน Photo ที่พบครบกับที่เลือก
  9. ใช้ Association("Photos").Append
เหตุผลของ Transaction: ถ้าสร้าง Tag สำเร็จแต่ Photo ID ไม่ครบ ระบบจะ Rollback ให้ ไม่เหลือข้อมูลครึ่ง ๆ กลาง ๆ

17. Tag Cloud คำนวณอย่างไร

Tag Cloud ต้องรู้ว่าแต่ละ Tag ถูกใช้กับกี่รูป จึงใช้ LEFT JOIN จาก tags ไป photo_tags 

err := r.db.Model(&models.Tag{}).
  Select("tags.id, tags.name, COUNT(DISTINCT photo_tags.photo_id) AS photo_count").
  Joins("LEFT JOIN photo_tags ON photo_tags.tag_id = tags.id").
  Group("tags.id, tags.name").
  Order("photo_count DESC").
  Order("tags.name ASC").
  Scan(&result).Error
ส่วนหน้าที่
LEFT JOINให้ Tag ที่ยังไม่มีรูปก็ยังปรากฏได้
COUNT(DISTINCT ...)นับรูปไม่ให้ซ้ำ
GROUP BYรวมผลตาม Tag แต่ละตัว
ORDER BY photo_count DESCTag ที่ใช้มากขึ้นก่อน

18. Search flow และ AND / OR

หน้า Search ส่ง tagNames และ mode ให้ SearchPhotos ซึ่งส่งต่อไป SearchPhotosByTags

OR

ตรงอย่างน้อยหนึ่ง Tag

ถ้าเลือก ทะเล และ ภูเขา รูปที่มีอย่างใดอย่างหนึ่งก็แสดง

ใช้ subquery, JOIN และ Distinct

AND

ต้องตรงครบทุก Tag

ถ้าเลือก ทะเล และ ภูเขา รูปต้องมีทั้งสอง Tag จึงจะแสดง

ใช้ Group และ Having Count

lowerTags := []string{"ทะเล", "ภูเขา"}

Where("LOWER(tags.name) IN ?", lowerTags)

Having(
  "COUNT(DISTINCT LOWER(tags.name)) = ?",
  len(lowerTags),
)
ป้องกัน SQL Injection: ใช้ Parameterized Query ผ่าน GORM ไม่เอาข้อความจากผู้ใช้ไปต่อเป็น SQL string โดยตรง

19. Error handling

ระบบมีหลายจุดที่อาจผิดพลาด จึงต้องแยกประเภท Error และไม่กลืน Error โดยไม่จำเป็น

จุดเกิด Errorตัวอย่างผลที่ระบบควรทำ
เปิด Databaseสร้าง directory ไม่ได้ / SQLite เปิดไม่ได้เก็บไว้ใน dbErr และแสดง Disconnected
เลือก Folderผู้ใช้กด Cancelไม่เปลี่ยน Path เดิม และไม่ถือเป็น Fatal Error
ค้นหาไฟล์Source ไม่มีอยู่จริงคืน Error จาก DiscoverImages
Copy fileไม่มีสิทธิ์เขียน / ชื่อซ้ำบันทึกผลล้มเหลวแยกรายการและส่ง Progress ต่อ
สร้าง Tagชื่อว่าง / ไม่ได้เลือก Photoคืน ErrEmptyTagName หรือ ErrNoPhotoIDs
SearchDatabase ไม่พร้อมFrontend แสดง Error State และให้ลองใหม่

20. Testing และคำสั่งตรวจงาน

Go test

ตรวจ Package ทั้งหมด รวม Database, Repository และ Backup

go test ./...

Nuxt build

ตรวจ TypeScript, Vue template และการ Build Frontend

cd frontend
npm run build

Wails dev

ต้องรันจากโฟลเดอร์ที่มี wails.json, main.go และ go.mod

cd photo-backup
wails dev

Wails binding

เมื่อเพิ่ม public API ใน Go ให้สร้าง binding ใหม่

wails generate module
ลำดับที่แนะนำ: แก้ Go → gofmt → go test → generate binding → แก้ Vue → npm build → wails dev

21. ไฟล์ไหนควร Commit

ไฟล์โดยทั่วไปเหตุผล
app.goCommit เมื่อแก้ APIเป็นโค้ด Backend จริง
internal/database/Commitเป็นโค้ดเปิด Database
internal/models/Commitเป็น schema ของระบบ
internal/repository/Commitเป็น Data access logic
frontend/app/pages/Commitเป็นหน้า Feature
frontend/wailsjs/ตรวจ Diff ก่อนCommit เมื่อเกิดจาก API ใหม่ที่ต้องใช้จริง
package.json.md5มักไม่ต้องเป็นไฟล์ Generated จากเครื่องมือ
node_modules/ไม่ CommitDependency ติดตั้งใหม่จาก package-lock

23. สรุปสุดท้าย

Database ของ PhotoBackup: คือไฟล์ SQLite ที่ถูกเปิดโดย internal/database/database.go แล้วส่ง *gorm.DB ไปให้ internal/repository/repository.go ส่วน app.go เป็นสะพานจาก Wails ไป Repository และ Nuxt เป็นหน้าจอที่เรียกสะพานนี้

ถ้าจะเพิ่ม Feature ใหม่ ให้คิดตามลำดับนี้เสมอ: Model ต้องเก็บอะไร → Repository ต้อง Query อะไร → app.go ต้องเปิด API อะไร → Wails ต้อง Generate binding อะไร → Vue ต้องแสดงผลและจัดการ Error อย่างไร

เอกสารนี้สร้างจากโครงสร้างและ Source Code ในโฟลเดอร์ photo-backup ของโปรเจกต์ PhotoBackup เปิดด้วย Browser ได้โดยตรง และใช้ปุ่มค้นหา/โหมดมืด/พิมพ์ PDF ได้
