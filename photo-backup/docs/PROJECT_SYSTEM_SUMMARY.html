1. ภาพรวมแนวคิดของระบบ

What the program solves

ผู้ใช้เลือกโฟลเดอร์ต้นทาง เช่น Flash Drive และเลือกโฟลเดอร์ปลายทาง จากนั้นระบบค้นหารูปภาพ, คัดลอกไปปลายทาง, ตรวจสอบว่าสำเนาตรงกับต้นฉบับ, บันทึกประวัติลง SQLite และสร้างงานวิเคราะห์ AI แบบแยกจาก Backup

เลือก Source→ค้นหา JPG/PNG→Copy→Verify→Save DB→สร้าง Tag Job→Search/Tag Cloud

จุดสำคัญด้านข้อมูล

ระบบไม่ลบต้นฉบับก่อน Copy, Verify และบันทึกข้อมูลสำเร็จ การ Backup ซ้ำใช้การตรวจประวัติและไม่เขียนทับไฟล์เดิม

จุดสำคัญด้าน AI

AI อ่านไฟล์ปลายทางที่ตรวจสอบแล้ว ไม่อ่านต้นฉบับโดยตรง และใช้ Content Hash เพื่อใช้ผลเดิมซ้ำโดยไม่วิเคราะห์ซ้ำ

10. Backup Flow แบบละเอียด

service/backup.go
Discover→ValidateImage→CopyImage O_EXCL→EqualFiles→SHA256File→SaveBackup Transaction→AI Job→ลบต้นฉบับ
  1. ค้นหา: backup.DiscoverImages() เดิน Directory แบบ Recursive และรับเฉพาะ .jpg/.jpeg/.png
  2. คัดลอก: backup.CopyImage() เปิดปลายทางด้วย O_EXCL จึงไม่เขียนทับไฟล์เดิม ถ้าชื่อซ้ำจะใช้ (1), (2)
  3. Verify: เปรียบเทียบข้อมูลด้วย backup.EqualFiles() และตรวจขนาดไฟล์
  4. Hash: analysis.SHA256File() อ่านเป็น Chunk ไม่โหลดทั้งไฟล์เข้า RAM
  5. Database: repository.SaveBackup() บันทึก Photo และ FileRecord ใน Transaction
  6. ลบต้นทาง: Service เรียก finishMove() หลัง Copy + Verify + Save DB สำเร็จเท่านั้น ถ้าลบไม่ได้จะเก็บทั้งต้นทางและปลายทางพร้อมรายงานสถานะ

11. AI Pipeline

วิเคราะห์หลัง Backup

AI ทำงานแยกจาก Backup ผ่าน Persistent Job Queue ใน service/ai_queue.go เมื่อ Backup สำเร็จและมี ContentHash ระบบจะเรียก enqueueAIJob() แล้ว Worker อ่าน Job ไปประมวลผล

AIJob queued→Claim→ตรวจ BackupPath + Hash→ค้น Cache→วิเคราะห์ YOLO/BLIP→Save Result + Tags→completed

ถ้าปิดโปรแกรมระหว่างทำงาน ResetProcessingAIJobs() จะคืน Job ที่ค้างจาก processing เป็น queued เมื่อเปิดใหม่ ส่วน Job ที่ failed จะถูกนำกลับคิวระหว่าง Reconcile หากรูปยังไม่มี Description

YOLO

analysis/yolo.go เปิด Worker แบบ JSON Lines ค้างไว้ ใช้ tools/yolo_worker.py หรือ Portable tools/bin/windows/yolo_worker.exe เพื่อสร้าง Tag วัตถุ

BLIP + OPUS-MT

analysis/blip.go ส่งภาพให้ Portable BLIP สร้าง Description แล้วใช้ OPUS-MT แปลเป็นภาษาไทยแบบ Local

CombinedAnalyzer

analysis/router.go เรียก YOLO และ BLIP พร้อมกัน แล้วรวม Tag/Description โดยความสำเร็จของตัวหนึ่งไม่ถูกทิ้งเพราะอีกตัวล้มเหลว

Cache

repository.SaveAIResultAndApply() บันทึก AIResult และนำ Description/AI Tags ไปใช้กับรูปใน Transaction เดียวกัน ไม่ส่งภาพ ContentHash เดิมไป AI ซ้ำ

Tag Source: Tag ที่ AI สร้างใช้ source=ai, Tag ผู้ใช้ใช้ source=user เมื่อ ContentHash เปลี่ยน ระบบลบเฉพาะ AI Tag ของผลเก่า ไม่ลบ Tag ที่ผู้ใช้เพิ่มเอง

12. Portable AI สำหรับเพื่อน

สิ่งที่ทำเสร็จแล้ว

มี Portable YOLO Worker สำหรับ Windows แล้ว เพื่อนที่มี Go, Node.js และ Wails CLI สามารถ Pull โค้ดแล้วสั่ง wails dev ได้โดยไม่ต้องติดตั้ง Python, Ultralytics หรือ Ollama เพิ่มเพื่อใช้ Tag

models/yolo11n.pt
tools/bin/windows/yolo_worker.exe

Go จะค้นหาไฟล์จากโฟลเดอร์ Bundle ผ่าน analysis/yolo.go และถ้าไม่พบ Portable Worker จึงค่อย fallback ไปหา Python Worker

ข้อจำกัด: Portable ที่ทำเสร็จตอนนี้คือ YOLO/Tag การสร้าง Description ยังเป็น Optional ผ่าน Ollama หากต้องการ Description แบบไม่ติดตั้งอะไรเลย ต้อง Bundle Caption Runtime + Vision Model แยก และต้องทำ Binary สำหรับ Windows/macOS

15. ข้อจำกัดและสิ่งที่ต้องรู้

พูดตามจริง

ระบบปฏิบัติการ

Source Code เป็น Cross-platform แต่ Portable Worker ที่สร้างแล้วเป็น Windows จึงต้อง Build Worker แยกสำหรับ macOS

ขนาดไฟล์

Portable Worker รวม PyTorch/Ultralytics จึงมีขนาดใหญ่ ควรใช้ Git LFS หรือส่ง ZIP แยก ไม่ควรยัดไฟล์ใหญ่ลง Git ปกติหาก Remote จำกัดขนาด

Description

Ollama ไม่มี API Limit เพราะทำงาน Local แต่ต้องติดตั้ง Ollama และดาวน์โหลดโมเดล ส่วนโหมดไม่ติดตั้งใช้ YOLO Tag เป็นหลัก

ColorTag

ฟิลด์ ColorTag และ Source color ยังอยู่เพื่อความเข้ากันได้กับข้อมูลเดิม แต่ตัววิเคราะห์สีอัตโนมัติเดิมถูกนำออกจาก Analysis Pipeline แล้ว
