1. แผนผังไฟล์สำคัญ

อ่านตามเส้นทางนี้จะเข้าใจระบบเร็วที่สุด

main.goเปิด Wailsสร้าง App, เรียก wails.Run, กำหนด OnStartup/OnShutdown และ Bind app
app.goApplication APIถือ context, Database, Repository และประกาศ Method เช่น GetPhotoCount, StartBackup, SearchPhotos
internal/database/database.goเปิด SQLiteหา Path ที่ใช้ได้หลาย OS, สร้างโฟลเดอร์, เปิด GORM, AutoMigrate และ Close
internal/models/photo.goModel Photoกำหนด field ของรูปภาพและความสัมพันธ์กับ Tag
internal/models/tag.goModel Tagกำหนดชื่อ Tag และความสัมพันธ์ many-to-many กับ Photo
internal/repository/repository.goData accessรวมคำสั่ง GORM: Create, Find, Count, Association, JOIN, Search และ Tag Cloud
frontend/wailsjs/go/main/App.*Generated bindingWails สร้างจาก public Go method เพื่อให้ Vue import ใช้งาน
frontend/app/pages/*.vueหน้าจอ NuxtDashboard, Backup, Tags, Search เรียก API และแสดงผล
wails.jsonWails configกำหนดคำสั่ง npm install, build, dev watcher และชื่อ output

3. SQLite อยู่ตรงไหนและติดต่ออย่างไร

3.1 การหา Path แบบไม่ Hardcode

ไฟล์ internal/database/database.go ใช้ os.UserConfigDir() แล้วต่อชื่อโฟลเดอร์ด้วย filepath.Join จึงไม่ผูกกับ Drive หรือชื่อ User ของเครื่องใดเครื่องหนึ่ง

// database.go
baseDir, err := os.UserConfigDir()
return filepath.Join(baseDir, "PhotoBackup", "photo-backup.db"), nil

Windows

ระบบเลือก Config directory ของผู้ใช้ แล้วสร้างโฟลเดอร์ PhotoBackup ภายในนั้น

macOS

ใช้ Config directory ของ macOS และประกอบ Path ด้วย filepath.Join เช่นเดียวกัน

3.2 เปิด Database

directory := filepath.Dir(path)
os.MkdirAll(directory, 0755)
conn, err := gorm.Open(sqlite.Open(path), &gorm.Config{})
conn.AutoMigrate(&models.Photo{}, &models.Tag{})

gorm.Open สร้าง connection ผ่าน SQLite driver ส่วน AutoMigrate ตรวจ Model แล้วสร้าง/ปรับตารางให้ตรงกับ struct

3.3 ปิด Database

app.shutdown เรียก a.database.Close() → ดึง underlying *sql.DB จาก GORM → ปิด connection คืน resource

ข้อควรเข้าใจ: Database ไม่ใช่ go.mod หรือไฟล์ JSON ใน Frontend แต่คือไฟล์ SQLite จริงชื่อ photo-backup.db ที่ถูกสร้างตอนเปิดโปรแกรม

5. Repository และ GORM

Repository เป็นชั้นที่สัมผัส Database โดยตรง หน้า Nuxt ไม่ควรรู้ว่าใช้ SQLite หรือเขียน SQL อย่างไร

type Repository struct { db *gorm.DB }
func New(db *gorm.DB) *Repository { return &Repository{db: db} }

Photo operations

CreatePhoto → INSERT Photo
ListPhotos → โหลดรูป + Preload Tags
RecentPhotos → เรียงวันที่และ Limit
CountPhotos → นับจำนวนแถว

Tag operations

AddTagToPhotos → Trim, กัน ID ซ้ำ, Transaction, FirstOrCreate, Association.Append
RemoveTagFromPhoto → ลบความสัมพันธ์เท่านั้น
GetTagCloud → JOIN + COUNT

ตัวอย่าง CountPhotos

var count int64
err := r.db.Model(&models.Photo{}).Count(&count).Error
return count, err

GORM จะสร้าง SQL แนวคิดประมาณ SELECT COUNT(*) FROM photos แล้วคืนตัวเลขให้ app.go

ทำไมต้อง Preload("Tags")

ถ้าเรียก Find(&photos) อย่างเดียว จะได้ข้อมูล Photo แต่ field Tags อาจยังไม่ถูกโหลด การใช้ Preload("Tags") ทำให้ GORM ไปอ่านความสัมพันธ์จาก photo_tags และ tags เพิ่ม

8. Backup flow

  1. กดเลือกต้นทาง → SelectSourceFolder เปิด Native Dialog
  2. กดเลือกปลายทาง → SelectDestFolder
  3. กด Start → StartBackup(sourcePath, destPath)
  4. ค้นหารูปด้วย DiscoverImages แบบ recursive และกรอง jpg/jpeg/png
  5. คัดลอกด้วย CopyFiles และส่ง event backup:progress
  6. ผลสำเร็จถูกสร้างเป็น models.Photo
  7. repo.CreatePhoto(photo) เขียนลง SQLite
  8. Dashboard เรียก Count ใหม่จึงเห็นจำนวนเพิ่ม
photo := &models.Photo{
OriginalName: result.OriginalName,
OriginalPath: result.OriginalPath,
BackupPath: result.BackupPath,
FileSize: result.FileSize,
BackedUpAt: time.Now(),
}
a.repo.CreatePhoto(photo)

9. Tag flow

  1. โหลดรูปด้วย GetTaggedPhotos
  2. เลือกหลาย Photo และพิมพ์ชื่อ Tag
  3. เรียก AddTagToPhotos(photoIDs, name)
  4. Repository Trim ชื่อและตรวจจำนวน ID
  5. Transaction ทำ FirstOrCreate Tag
  6. โหลด Photo ตาม ID และตรวจว่าพบครบ
  7. ใช้ Association Append เขียน photo_tags
  8. Tag Cloud ใช้ LEFT JOIN + COUNT และเรียงจำนวนมากไปน้อย
SELECT tags.id, tags.name,
COUNT(DISTINCT photo_tags.photo_id) AS photo_count
FROM tags LEFT JOIN photo_tags
ON photo_tags.tag_id = tags.id
GROUP BY tags.id, tags.name
ORDER BY photo_count DESC;
Transaction สำคัญ: ถ้าขั้นตอนใดล้มเหลว จะไม่เกิด Tag หรือความสัมพันธ์ที่บันทึกค้างเพียงครึ่งเดียว

10. Search flow และ AND / OR

SearchPhotos(tagNames, mode) ส่งชื่อ Tag และโหมดจากหน้า Search ไปยัง Repository

OR

ตรงอย่างน้อยหนึ่ง Tag

JOIN Photo/Tag แล้วเลือก ID ที่ตรง Tag ใดก็ได้ ใช้ Distinct ป้องกันรูปซ้ำ

AND

ต้องตรงครบทุก Tag

Group ตาม Photo และใช้ Having Count ของ Tag ที่ไม่ซ้ำเท่ากับจำนวน Tag ที่เลือก

Where("LOWER(tags.name) IN ?", lowerTags)
Having("COUNT(DISTINCT LOWER(tags.name)) = ?", len(lowerTags))

การใช้ LOWER ทำให้ไม่สนใจตัวพิมพ์เล็กใหญ่ และการส่งค่าแบบ parameter ผ่าน GORM ช่วยลดความเสี่ยง SQL Injection
